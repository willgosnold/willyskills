# pstack in T3 Code

pstack skills use Cursor names. When the T3 Code MCP tools are present (`delegate_task`, `orchestrator_capabilities`), read this file once per session, after your agent's adapter. For subagents, scheduling, pull requests, transcripts, and models, this file's rows replace the agent adapter's rows. `<pstack>` means the folder that holds `skills/`, `agents/`, and `docs/`. If a Cursor field has no row in either file, drop it and say so. Never pass a field or value the tool schema rejects.

Call `orchestrator_capabilities` once before the first spawn. It lists the providers and models you can target and returns your own thread ID as `parentThreadId`. Trust it over this file. If it shows a provider cannot run child tasks, that provider is unavailable.

## Subagents

| Cursor | T3 |
| --- | --- |
| `Task` | `delegate_task`. Put the whole brief in `task`. The child gets no conversation history. Give each spawn its own `clientRequestId`, and reuse it only to retry that same spawn. Keep the returned `taskId` and `childThreadId`. |
| Spawn N workers in one message | N `delegate_task` calls in one message. |
| `subagent_type: poteto-agent` | No type field. Start the brief with: "Read `<pstack>/agents/poteto-agent.md` and act as that agent. The poteto-mode skill is at `<pstack>/skills/poteto-mode/SKILL.md`." Use absolute paths. |
| `subagent_type: comment-sicko` | The same, with `<pstack>/agents/comment-sicko.md`. |
| `subagent_type: generalPurpose` | No type field and no role line. |
| `readonly: true` | The brief says "Do not edit, create, commit, or push files." Run `git status` in the checkout afterward. Leave `runtimeMode` unset. A narrower mode makes the child wait for approvals no one can give. |
| `readonly: false` | Omit. |
| `environment: "cloud"` | `isolation: "worktree"`. The child gets its own checkout of the parent's current local commit. Uncommitted edits are not copied, so commit first or name a pushed branch. |
| `environment: "local"` | Both run on this machine in T3. A worker that writes still gets `isolation: "worktree"`. A worker that only reads gets no `isolation` and shares your checkout. |
| `cloud_base_branch: <b>` | `isolation: "worktree"`, and the brief tells the worker to check out `<b>` first. |
| `run_in_background: true` | `mode: "async"`. Its completion wakes this thread. End your turn instead of polling. Use `task_status` only when you need a result mid-turn. |
| `run_in_background: false` | `mode: "wait"`. On `waitTimedOut`, keep the `taskId` and check `task_status` later. |
| `resume` an agent | `t3_thread_send` to its `childThreadId`. A finished task then runs a new follow-up task with its own `taskId`. For a fresh review round, call `delegate_task` again with the consolidated brief instead. |
| Stop an agent | `task_cancel`, then confirm with `task_status`. Cancelling also stops the tasks it delegated. |
| Check an agent's status in the Cursor dashboard | `task_status`. It reads state without waking the agent. |
| The child asks a question (`hasPendingQuestion`) | `t3_pending_request_read` and `t3_pending_request_respond` with `threadId: <childThreadId>`, or ask the user. |
| `is_background: true` in an agent file | Ignore. `mode` sets this per spawn. |

## Models

The model choices here are provisional. They let Phase 0 run while model roles are still undecided.

Budget: every child runs on Claude, at `low` or `medium` effort only. Use `medium` where the skill asks for `high` or above, and `low` for routine or mechanical work. Never set `fastMode`. Never target Codex. A panel that asks for several model families therefore runs on Claude only. Say so in the reply.

| Cursor | T3 `target` |
| --- | --- |
| `claude-<family>-<version>-<effort>[-fast]`, such as `claude-opus-5-5-xhigh` | `{providerInstanceId: "claudeAgent", model: "claude-<family>-<version>", options: {effort: <effort within budget>}}`. Drop `-fast`. |
| `grok-<...>`, `gpt-<...>`, or any other non-Claude slug | `{providerInstanceId: "claudeAgent", model: "claude-sonnet-5-5", options: {effort: <effort within budget>}}`. Drop `-fast`. |
| `auto` or `inherit-parent` | Omit `target`. |
| The `pstack-models.mdc` rule | None exists yet. Use the skill's default slug and map it with these rows. `setup-pstack` has nothing to write, so say so and stop. |

## Waiting and schedules

| Cursor | T3 |
| --- | --- |
| `/loop <interval> <prompt>` | `schedule_task` with `schedule: {type: "interval", everyMs: <ms>}` (minimum 60000) and the prompt. Report `nextRunAt`. Delete it with `delete_scheduled_task` once the loop's predicate holds. |
| `/loop until <predicate>` with no interval | Wake on the event if T3 can see it: a child finishing (`mode: "async"`) or a pull request change (`watch_pull_request`). Add a `schedule_task` heartbeat of 20 to 30 minutes in case the event never arrives. Each wake re-checks the predicate. |
| A watcher subagent that wakes you on an event | The same: `watch_pull_request` for a pull request, otherwise an async `delegate_task` whose brief polls and returns when the event happens. |

## Pull requests

| Cursor | T3 |
| --- | --- |
| Cursor's built-in pull request tool | None. Use `gh`, or `origin` where the skill says so. |
| Any pull request you open or take over | `link_pull_request` with its URL right after you create it, once for every layer of a stack. Before finishing, check `list_thread_pull_requests`. |
| Waiting on CI, reviews, or comments | `watch_pull_request`, then end your turn. It wakes you when a check fails, required checks pass, someone else comments or reviews, or the branch starts to conflict. A merge ends the watch without waking you, so pair it with a `schedule_task` heartbeat when you wait for a merge. `scripts/watch-pr` stays the source of the verdict. |
| Handing the work back to the user | `unwatch_pull_request` first. |

## Transcripts

| Cursor | T3 |
| --- | --- |

## Paths

| Cursor | T3 |
| --- | --- |
| The agent's store (path in the system prompt) | T3 names none. Use `~/.local/state/pstack/<repo>/`, where `<repo>` is the main checkout's folder name, from `basename "$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")"`. It sits outside every worktree, so the coordinator and its worktree children share it. Create it if it is missing. |

## Cursor-only features

Bugbot comments can still appear on a GitHub pull request, so triage them as the skill says. Cursor automations, cloud agents, the Cursor dashboard, and a Cursor restart have no T3 equivalent. Say so, skip that step, and continue. Unverified: whether async children survive a T3 Code restart. After a restart, check each `taskId` with `task_status` before assuming it is dead.
